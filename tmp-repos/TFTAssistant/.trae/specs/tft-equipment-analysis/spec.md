# TFT Assistant - 装备分析增强 - Product Requirement Document

## Overview
- **Summary**: 增强 TFT Assistant 的装备分析功能，整合英雄装备的前四率和登顶率数据，区分装备类型（神器、光明装备、成装和散件），考虑经济价值，并实现实时数据计算，为玩家提供更全面的装备分析和推荐。
- **Purpose**: 帮助玩家做出更明智的装备选择决策，了解不同装备的实际价值和效果，提升游戏表现。
- **Target Users**: 云顶之弈/金铲铲玩家，特别是希望提升装备选择策略的进阶玩家。

## Goals
- 整合英雄装备的前四率和登顶率数据
- 区分装备类型（神器、光明装备、成装和散件）
- 考虑装备的经济价值
- 实现实时数据计算，整合所有相关数据
- 为玩家提供基于数据分析的装备推荐
- 确保所有功能符合 Riot 第三方工具政策

## Non-Goals (Out of Scope)
- 不提供实时胜率预测（Riot 禁止）
- 不提供对手装备分析（Riot 禁止）
- 不修改游戏客户端或内存（Riot 禁止）
- 不爬取或窃取第三方网站数据（遵守版权）
- 不展示实时游戏数据（Riot 禁止）

## Background & Context
- 装备选择是云顶之弈/金铲铲中非常重要的决策因素
- 不同装备类型（神器、光明装备、成装、散件）有不同的获取方式和价值
- 装备的前四率和登顶率数据能帮助玩家了解装备的实际效果
- 经济价值分析能帮助玩家在有限的经济条件下做出最优选择
- TFTAssistant 已经具备基础的装备分析功能，需要进一步增强

## Functional Requirements
- **FR-1**: 装备类型管理
  - 区分并管理不同类型的装备：神器、光明装备、成装和散件
  - 跟踪成装与散件的合成关系
  - 考虑不同装备类型的获取方式差异

- **FR-2**: 装备数据整合
  - 整合英雄装备的前四率和登顶率数据
  - 考虑装备的经济价值
  - 分析装备在不同阵容中的表现
  - 分析装备在不同段位中的表现

- **FR-3**: 实时数据计算
  - 基于整合的数据计算装备价值
  - 考虑装备的合成路径和经济成本
  - 实现装备优先级算法
  - 提供实时装备推荐

- **FR-4**: 装备推荐系统
  - 基于当前棋盘状态推荐装备
  - 考虑玩家的经济状况
  - 考虑装备的获取概率
  - 提供装备合成路径建议

- **FR-5**: UI 集成
  - 在覆盖层中展示装备分析结果
  - 在桌面主窗口中提供详细的装备分析
  - 支持装备数据筛选和排序

## Non-Functional Requirements
- **NFR-1**: 数据更新频率
  - 装备数据更新频率不超过每日一次
  - 本地缓存机制，减少网络请求

- **NFR-2**: 性能
  - 数据计算时间 < 1 秒
  - UI 响应流畅，无明显卡顿
  - 内存占用合理

- **NFR-3**: 可靠性
  - 数据来源不可用时的降级策略
  - 错误处理和恢复机制
  - 数据一致性检查

- **NFR-4**: 合规性
  - 所有数据展示明确标注为历史统计
  - 遵守 Riot 第三方工具政策
  - 遵守第三方数据来源的使用条款

- **NFR-5**: 可扩展性
  - 支持新装备类型的添加
  - 支持新赛季装备数据的更新
  - 支持不同游戏模式的装备分析

## Constraints
- **Technical**:
  - 后端使用 .NET 8.0 LTS + C# 12.0
  - 数据库使用 SQLite
  - 必须遵守第三方数据来源的使用限制
  - 必须符合 Riot 第三方工具政策

- **Business**:
  - 免费使用层级的数据获取限制
  - 尊重第三方数据来源的版权和使用条款
  - 不直接展示第三方网站的原始数据

- **Dependencies**:
  - 外部大数据网站的 API 或数据导出
  - 网络连接（用于数据更新）
  - 本地存储空间（用于数据缓存）

## Assumptions
- 外部数据来源提供装备的前四率和登顶率数据
- 数据获取频率符合第三方网站的使用政策
- 用户理解装备分析结果仅供参考，不保证游戏胜利
- 装备分析结果明确标注为历史统计数据

## Acceptance Criteria

### AC-1: 装备类型管理
- **Given**: 系统已获取装备数据
- **When**: 分析装备类型
- **Then**: 正确区分神器、光明装备、成装和散件，并识别成装与散件的合成关系
- **Verification**: `programmatic`

### AC-2: 装备数据整合
- **Given**: 系统已获取装备数据
- **When**: 整合装备数据
- **Then**: 成功整合英雄装备的前四率、登顶率、经济价值等数据
- **Verification**: `programmatic`

### AC-3: 实时数据计算
- **Given**: 玩家正在游戏中
- **When**: 系统分析当前游戏状态
- **Then**: 基于整合的数据计算装备价值和优先级
- **Verification**: `programmatic`

### AC-4: 装备推荐系统
- **Given**: 玩家正在游戏中
- **When**: 系统分析当前游戏状态
- **Then**: 提供基于数据分析的装备推荐
- **Verification**: `human-judgment`

### AC-5: UI 集成
- **Given**: 系统已获取装备数据
- **When**: 用户打开覆盖层或桌面主窗口
- **Then**: 装备分析结果正确显示，UI 响应流畅
- **Verification**: `human-judgment`

### AC-6: 合规性检查
- **Given**: 所有装备分析功能已实现
- **When**: 进行合规审查
- **Then**: 确认所有数据展示明确标注为历史统计，无实时预测功能
- **Verification**: `human-judgment`
